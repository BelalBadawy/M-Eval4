# Plan 1: Authentication, Authorization & User Provisioning with Excel Bulk Import

🔴 **Complex** — Multi-phase execution covering ASP.NET Core project scaffolding, EF Core data modeling with SQL Server, JWT auth with mandatory first-login password change, single active session model per user, fine-grained RBAC permission engine with role hierarchy, user lifecycle administration, Excel bulk import engine with DB staging/dry-run/cancellation/rollback, security hardening, and audit logging.

---

## 1. System Architecture & Foundational Rules

- **System Type:** Internal enterprise application. Zero public registration, no public activation links.
- **Provisioning Model:** Accounts created exclusively by Admins (individually or via Excel bulk import).
- **Default Credential & Configuration:**
  - Configured via `SecuritySettings:DefaultUserPassword` in `appsettings.json` / user secrets (e.g. `Mina@123`), **never hardcoded as a C# string literal**.
  - Seeded initial admin, single-user creation, and admin force-reset all resolve default credentials via `IOptions<SecuritySettings>`.
- **First-Login Security Gateway (P0):**
  - Newly created/imported accounts receive the configured default password with `MustChangePassword = true`.
  - The JWT token issued on login contains claim `must_change_password: true`.
  - **Gateway Enforcement (`FirstLoginGatewayFilter`):** Implemented as an endpoint filter on protected route groups (or middleware after `UseRouting`). While `must_change_password: true`, the user is blocked with `403 Forbidden` (`PasswordChangeRequired`), with exactly three whitelisted exceptions:
    1. `POST /api/v1/auth/change-password` (to replace the temporary password)
    2. `POST /api/v1/auth/refresh` (to refresh the session; `TokenService` reads DB state and issues a new access token still carrying `must_change_password: true`)
    3. `POST /api/v1/auth/logout` (to abandon the session)
  - Anonymous endpoints (`/login`, `/forgot-password`, `/reset-password`) are public and bypass the gateway filter completely.
  - `PasswordPolicyService` explicitly rejects new passwords matching the configured default password.
  - Successful password change updates `PasswordChangedAtUtc`, sets `MustChangePassword = false`, revokes the user's active session, and issues fresh JWT tokens.
- **Single Active Session Per User & Lightweight Replay Detection:**
  - The system maintains **at most one active refresh token per user** via a unique filtered index on `RefreshToken.UserId` where `RevokedAtUtc IS NULL`.
  - **New Login:** Revokes any existing active refresh token with reason `SupersededByNewLogin` before issuing the new one — one device wins.
  - **Refresh Rotation:** Validates current token -> revokes it with reason `Rotated` -> issues a new active token. No family tracking needed.
  - **Lightweight Reuse/Replay Detection:** If a token already revoked with reason `Rotated` is presented, the system treats it as suspicious: it immediately revokes the user's current active token (reason: `SuspiciousReplay`) and rejects the request with `401 Unauthorized`.
  - **All Lifecycle Events:** Password change, admin force-reset, forgot-password reset, account deactivation, role downgrade, admin force-logout, and rollback simply revoke the user's single active refresh token.
- **Password Reset Flow (`PasswordResetToken`):**
  - `POST /api/v1/auth/forgot-password`: Issues a 30-minute cryptographic reset token stored in `PasswordResetToken` (hashed) and dispatches email via `IEmailService`. Returns a uniform response whether or not the email exists (enumeration-safe). Rate-limited.
  - `POST /api/v1/auth/reset-password`: Validates and consumes single-use reset token (`UsedAtUtc`), enforces password policy, updates password, sets `MustChangePassword = false`, and revokes the active session.
  - Password history (tracking last N passwords) is explicitly deferred to a future module in `PRD.md`.
- **Admin Force-Reset (`force-reset-password`):**
  - Sets user password to configured default password, sets `MustChangePassword = true`, resets `PasswordChangedAtUtc = DateTime.UtcNow` (restarting the 14-day auto-suspend clock), revokes the active session, and notifies user via `IEmailService`.
  - Subsequent login with default password lands in the First-Login Gateway.
- **Auto-Suspension Background Worker (`DefaultPasswordInactivityWorker`):**
  - Daily `IHostedService` scanning for accounts still on the default password where `PasswordChangedAtUtc ?? CreatedAtUtc` > 14 days ago.
  - Deactivates the account (`IsActive = false`), writes a security audit entry, and notifies system administrators via `IEmailService`.
- **Role Isolation & Hierarchy:**
  - Default `User` role assigned automatically upon creation/import.
  - Roles and permissions are stored in normalized junction tables (`UserRoles`, `RolePermissions`), never as columns on `Users`.
  - `Role` entity includes `Level` (int): Super Admin = 100, Admin = 50, Auditor = 30, User = 10.
  - Admins cannot assign, modify, or create roles with `Level >= own level`. (An Admin at 50 cannot create or assign another Admin; only Super Admin can manage Admin accounts).
- **Soft-Deletion & Email Uniqueness:**
  - Filtered unique index in SQL Server on `Email` where `SoftDeletedAtUtc IS NULL`.
  - If an import batch contains an email belonging to a soft-deleted user, the row is rejected with reason: *"User with email is soft-deleted; requires manual administrator restore"*.
- **Excel Staging, Re-validation & Limits:**
  - Dedicated route namespace `/api/v1/imports/...`.
  - Template and import parser strictly accept only `Users` table columns (`FullName`, `Email`).
  - Strict limits enforced: Max file size 5 MB, max row count 5,000 rows.
  - Immediate rejection if headers include forbidden columns (`Role`, `Department`, `Password`).
  - Formula injection neutralization: sanitizes only leading characters (`=`, `+`, `-`, `@`), preserving internal hyphens (e.g. "Anne-Marie").
  - **Data Staging:** Dry-run stages validated records in an `ImportBatchRow` database table.
  - **Execute-Time Re-validation:** At execution time, `ImportProcessingWorker` re-checks database duplicates for "to-create" rows against the *live* DB state and applies the batch's chosen `DuplicateStrategy` (skip, update, or failRow).
  - **Purge Post-Execution:** Staged `ImportBatchRow` records are purged upon batch completion/failure/cancellation. `ImportRowError` records are retained with redacted/truncated PII.
  - Concurrency: Single active import lock in database; overlapping executions reject with `409 Conflict`.
  - Cancel support: `POST /api/v1/imports/{id}/cancel` sets status to `Cancelled` and `CancelledAtUtc = DateTime.UtcNow`.
  - Safe rollback: `POST /api/v1/imports/{id}/rollback` deactivates accounts *created* by that batch (`IsRolledBack = true`, `IsActive = false`), leaving pre-existing updated accounts untouched.
- **Account Lockout & Enumeration Resistance:**
  - Single source of truth for lockout: `LockoutEndUtc > DateTime.UtcNow`.
  - Increments `FailedLoginAttempts` up to threshold (5 attempts -> 15 min lockout).
  - Admin unlock: `POST /api/v1/users/{id:guid}/unlock` resets `FailedLoginAttempts = 0` and `LockoutEndUtc = null`.
  - Uniform timing and messages on `/login` and `/forgot-password` against enumeration.
- **Audit Immutability:**
  - `AuditLog` records are write-only. DbContext blocks `Update` and `Delete` operations on `AuditLog`.

## 4. Entity Model & Data Layer

1. **`User`**:
   - `Id` (Guid, PK)
   - `FullName` (nvarchar(150), required)
   - `Email` (nvarchar(255), normalized lowercase, filtered unique index where `[SoftDeletedAtUtc] IS NULL`)
   - `PhoneNumber` (nvarchar(30), nullable)
   - `PasswordHash` (nvarchar(255), required)
   - `MustChangePassword` (bool, default true)
   - `PasswordChangedAtUtc` (DateTime?, nullable)
   - `LockoutEndUtc` (DateTime?, nullable) — single source of truth for lockout
   - `FailedLoginAttempts` (int, default 0)
   - `IsActive` (bool, default true)
   - `Source` (`UserSource` enum: `Manual`, `Imported`)
   - `ImportBatchId` (Guid?, nullable FK to `ImportBatch`)
   - `IsRolledBack` (bool, default false)
   - `CreatedAtUtc`, `UpdatedAtUtc`, `SoftDeletedAtUtc` (DateTime?)
2. **`Role`**:
   - `Id` (Guid, PK), `Name` (nvarchar(50), unique), `Description` (nvarchar(255)), `Level` (int), `IsSystemProtected` (bool)
3. **`Permission`**:
   - `Id` (Guid, PK), `Code` (nvarchar(100), unique), `Description` (nvarchar(255)), `Module` (nvarchar(50))
4. **`UserRole`**:
   - `UserId` (FK), `RoleId` (FK), `AssignedAtUtc`, `AssignedByUserId` (FK)
5. **`RolePermission`**:
   - `RoleId` (FK), `PermissionId` (FK)
6. **`RefreshToken`** (Single active session per user):
   - `Id` (Guid, PK), `UserId` (FK), `TokenHash` (nvarchar(255)), `CreatedByIp` (nvarchar(50)), `CreatedAtUtc`, `ExpiresAtUtc`
   - `RevokedAtUtc` (DateTime?, nullable), `RevokedReason` (nvarchar(50), nullable: `SupersededByNewLogin`, `Rotated`, `SuspiciousReplay`, `UserLogout`, `PasswordChanged`, `AdminForceLogout`, `AccountDeactivated`, etc.), `RevokedByIp` (nvarchar(50), nullable)
   - **Filtered Unique Index:** Unique on `UserId` where `[RevokedAtUtc] IS NULL`.
7. **`PasswordResetToken`**:
   - `Id` (Guid, PK), `UserId` (FK), `TokenHash` (nvarchar(255)), `CreatedAtUtc`, `ExpiresAtUtc` (30 min), `UsedAtUtc` (DateTime?, nullable), `CreatedByIp` (nvarchar(50))
8. **`ImportBatch`**:
   - `Id` (Guid, PK), `FileName` (nvarchar(255)), `FileSize` (long), `TotalRows` (int), `ValidRows` (int), `InvalidRows` (int), `CreatedRows` (int), `UpdatedRows` (int), `FailedRows` (int)
   - `Status` (`ImportStatus` enum: `Pending`, `Validated`, `Processing`, `Completed`, `Failed`, `Cancelled`, `RolledBack`)
   - `DuplicateStrategy` (`DuplicateStrategy` enum: `Skip`, `Update`, `FailRow`)
   - `CommitPolicy` (`CommitPolicy` enum: `AllOrNothing`, `PartialValidOnly`)
   - `CreatedByUserId` (FK), `CreatedAtUtc`, `CompletedAtUtc`, `CancelledAtUtc`
9. **`ImportBatchRow`** (Staging table between dry-run and execute; purged post-execution):
   - `Id` (Guid, PK), `BatchId` (FK), `RowNumber` (int), `FullName` (nvarchar(150)), `Email` (nvarchar(255)), `Status` (`RowStatus` enum)
10. **`ImportRowError`**:
    - `Id` (Guid, PK), `BatchId` (FK), `RowNumber` (int), `ColumnName` (nvarchar(50)), `Reason` (nvarchar(255)), `RawValue` (nvarchar(100), truncated/redacted)
11. **`AuditLog`** (Immutable):
    - `Id` (Guid, PK), `ActorUserId` (Guid?, nullable), `Action` (nvarchar(100)), `EntityType` (nvarchar(50)), `EntityId` (nvarchar(100)), `Details` (nvarchar(max) JSON), `IpAddress` (nvarchar(50)), `TimestampUtc` (DateTime)
