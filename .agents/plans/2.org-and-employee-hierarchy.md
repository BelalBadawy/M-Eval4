# Plan 2: Organization Structure & Employee Reporting Hierarchy (Module 2 — `ORG`)

🔴 **Complex** — Multi-phase execution covering external integer PK lookups (Companies, Departments, Sections, Positions), Employee master entity with composite placement integrity, self-referencing manager hierarchy with overlaid-graph cycle detection, dual-identity 1:1 linkage to Module 1 Users, local-only column preservation, synchronous 5-sheet HR import engine with offboarding cascade, and audit logging.

## 2. Tasks

- [x] **Task 1: Domain Models, EF Core Schema & Migration**
  - Create entities: `Company`, `Department`, `Section`, `Position`, `Employee` in `backend/Models/`.
  - Configure in `AppDbContext`: `.ValueGeneratedNever()` on PKs, composite alternate keys on `Departments` and `Sections`, composite FKs on `Employees`, check constraints (`CK_Empl_SectionNeedsDept`, `CK_Empl_StatusDates`, `CK_Empl_ResignationAfterHire`, `CK_Positions_NLevel`), filtered indexes on `UX_Employees_Email` and `UX_Employees_UserId`, delete behavior `Restrict`.
  - Add EF Core migration `AddOrgAndEmployeeHierarchy`.
  - Test migration Up and reversible Down against local SQL Server.
  - *Validation:* Run database constraint tests `OrgConstraintTests.cs`.

- [x] **Task 2: DTOs, Permissions Seeding & DI Registration**
  - Create `backend/DTOs/OrgDtos.cs`, `EmployeeDtos.cs`, `OrgImportDtos.cs`.
  - Update `backend/Data/DbSeeder.cs`: Add permissions `org.read`, `org.import`, `employees.manage-eligibility`, `employees.link-user`. Map to `Admin` (all 4), `Auditor` (`org.read`), `Super Admin` (all).
  - Update `backend/Program.cs`: Register new services in DI container.
  - *Validation:* Run DbSeeder tests verifying 16 total permissions seeded and assigned.

- [x] **Task 3: Hierarchy Graph Service & Anomaly Detection**
  - Create `IHierarchyService` and `HierarchyService`:
    - Overlaid-graph cycle detection (`file rows ∪ existing DB employees`).
    - Manager validation (active, same company).
    - Upward manager chain traversal capped at 100 hops (returns both `PositionId` and `PositionName`).
    - Direct reports retrieval.
    - Hierarchy anomaly audit: Orphans (`DirectManagerId == null && NLevel > 1`), Root-with-manager (`DirectManagerId != null && NLevel == 1`), Mismatches (inactive/cross-company managers).
  - *Validation:* Run `HierarchyServiceTests.cs` (detecting direct self-loops, indirect cycles, 100-hop cap, orphans, and NLevel 1 with manager anomaly).

- [x] **Task 4: Employee & Organizational Structure Services**
  - Create `IOrgStructureService` and `OrgStructureService`: Active-only structure tree and lookup lists.
  - Create `IEmployeeService` and `EmployeeService`:
    - Search & paged query with filters (`companyId`, `departmentId`, `sectionId`, `positionId`, `managerId`, `nLevel`, `status`, `isEvaluationEligible`, `hasLinkedAccount`).
    - Eligibility override with `EligibilityChanged` audit log.
    - User account linking: validates target user existence and active status, rejects double-linking with `409 Conflict`, records `UserLinked` / `UserUnlinked` audit logs.
  - *Validation:* Run `EmployeeServiceTests.cs` and `EmployeeLinkingTests.cs`.

- [x] **Task 5: Synchronous HR Import Engine & Offboarding Cascade**
  - Create `IOrgImportService` and `OrgImportService`:
    - 5-sheet template generator (`Companies`, `Departments`, `Sections`, `Positions`, `Employees`).
    - Limits: 5 MB / 5,000 rows.
    - Concurrency: In-memory `SemaphoreSlim(1, 1)` shared between dry-run and execute (`409 Conflict`).
    - Validation: Lookup renames allowed; re-parenting rejected as row error; informational columns matched to lookup entities; employee ID↔Number immutability; formula neutralization; pre-validation of active email uniqueness.
    - In-memory manager resolution + overlaid cycle detection.
    - Atomic transaction: upsert lookups, upsert employees with managers, preserve local columns (`IsEvaluationEligible`, `UserId`, `IsActive`), untouched absent employees.
    - **Offboarding cascade (`ORG-026`):** Status change to Resigned/Terminated deactivates linked user, revokes session (`RevokedReason.EmployeeOffboarded`), writes `EmployeeOffboarded` audit log.
    - Audit logging: writes `OrgImportExecuted` on success, `OrgImportFailed` on failure.
  - *Validation:* Run `OrgImportServiceTests.cs` and `OffboardingCascadeTests.cs`.
