# 1. ASP.NET Core Minimal APIs with EF Core and SQL Server Stack

- **Status:** Accepted
- **Date:** 2026-09-04

## Context

The system previously contemplated a Python/FastAPI backend. The architecture is now defined as ASP.NET Core Minimal APIs with Entity Framework Core (EF Core) targeting a local SQL Server instance, paired with a React 19 + TypeScript + Vite frontend.

The application is strictly internal with no public registration or email activation links. User accounts are provisioned exclusively by Administrators (manually or via bulk Excel import) with a temporary default password (`Mina@123`).

## Decision

1. **Backend Framework & Architecture:**
   - ASP.NET Core Minimal APIs (.NET 9 / 10) in `backend/`.
   - Business rules and authorization logic live strictly in ASP.NET Core domain/application services, never in React.
   - OpenAPI specification exported to `backend/openapi.json` for frontend client generation (`openapi-typescript` / `openapi-fetch`).

2. **Database & ORM:**
   - Microsoft SQL Server (Localhost) as the relational database.
   - Entity Framework Core (`Microsoft.EntityFrameworkCore.SqlServer` & `Microsoft.EntityFrameworkCore.Design`) for data access and migrations.
   - Filtered unique indexes:
     - `Email` where `[SoftDeletedAtUtc] IS NULL` (allows re-creation after soft delete).
     - `RefreshToken.UserId` where `[RevokedAtUtc] IS NULL` (enforces single active session per user).
   - Migrations managed via `dotnet ef migrations add <Name> --project backend` and applied via `dotnet ef database update --project backend`.
   - Every migration must be reversible with a verified `Down()` method.
   - Audit immutability: `AuditLog` records are write-only; updates and deletions are blocked at the DbContext level.

3. **Authentication & Password Security:**
   - Bearer JWT token authentication architecture.
   - Passwords hashed using `BCrypt.Net-Next` (work factor 11–12 configurable).
   - Default password (`Mina@123`) loaded from configuration (`IOptions<SecuritySettings>`), never hardcoded in source code.
   - Password policy rejects passwords matching the configured default password. Password history tracking is deferred.
   - Single source of truth for lockout: `LockoutEndUtc > DateTime.UtcNow` (5 failed attempts -> 15 min lockout; admin unlock available).
   - Password reset via single-use, 30-minute `PasswordResetToken` entities with enumeration-safe uniform responses.

4. **Single Active Session Per User:**
   - System maintains at most one active refresh token per user via the filtered unique index.
   - **One device wins:** A new login revokes any existing active token (`SupersededByNewLogin`) before issuing the new one.
   - **Rotation:** Refreshing revokes current token (`Rotated`) and issues a replacement.
   - **Lightweight replay detection:** Presenting a token already revoked with reason `Rotated` revokes the user's current active token (`SuspiciousReplay`) and returns `401 Unauthorized`.
   - **Unified lifecycle revocation:** Password changes, admin force-resets, password resets, account deactivations, role downgrades, admin force-logouts, and rollbacks revoke the user's single active refresh token.

5. **First-Login Security Gateway (P0):**
   - Accounts created or force-reset receive `MustChangePassword = true` and an initial role of `User`.
   - `FirstLoginGatewayFilter` blocks all endpoints with `403 Forbidden` (`PasswordChangeRequired`) when `must_change_password` claim is `true`, except `/change-password`, `/refresh`, and `/logout`.
   - Background `IHostedService` auto-suspends accounts remaining on the default password beyond the 14-day grace period and notifies administrators.

6. **Role Isolation & Hierarchy:**
   - Core roles (`Super Admin` [100], `Admin` [50], `Auditor` [30], `User` [10]) with `IsSystemProtected` flags.
   - Role hierarchy: Callers cannot assign, modify, or create roles with `Level >= own level` (e.g. Admin at 50 cannot create or assign another Admin; only Super Admin can manage Admins).
   - Authorization implemented via `.RequirePermission("code")` endpoint extension and custom authorization handler.

7. **Excel Bulk Provisioning Engine:**
   - Dedicated route namespace `/api/v1/imports/...`.
   - Strict schema boundary: only `Users` table columns (`FullName`, `Email`) accepted. Forbidden columns (`Role`, `Department`, `Password`) cause immediate rejection.
   - Formula injection sanitization: neutralizes leading `=`, `+`, `-`, `@` while preserving internal hyphens.
   - Limits: 5 MB file size and 5,000 rows.
   - Two-phase staging: Dry-run validates and stages rows in `ImportBatchRow` DB table; execute reads from DB, re-checks live DB duplicates, applies `DuplicateStrategy` (skip/update/fail), and purges staged rows on completion.
   - Concurrency & Rollback: Single active import lock (`409 Conflict`). Soft rollback deactivates batch-created users (`IsRolledBack = true`, `IsActive = false`) preserving audit records.

8. **Frontend:**
   - React 19 + TypeScript + Vite + Tailwind CSS v4.0 + shadcn/ui in `frontend/`.

## Consequences

- Direct integration with enterprise .NET tooling, Visual Studio / VS Code, and SQL Server.
- Safe, audited schema evolution using EF Core code-first migrations with rollback verification.
- Replaces Python tooling with standard .NET CLI (`dotnet build`, `dotnet test`, `dotnet run`, `dotnet ef`).
- Strong, defense-in-depth internal authentication model with minimal session complexity and zero orphan tokens.
