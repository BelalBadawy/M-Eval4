# 2. Integer Identity Primary and Foreign Keys

- **Status:** Accepted
- **Date:** 2026-09-04

## Context

The initial scaffolding contemplated `Guid` (`uniqueidentifier` in SQL Server) for primary keys and foreign keys across entities (`User`, `Role`, `Permission`, `RefreshToken`, `PasswordResetToken`, `ImportBatch`, `ImportBatchRow`, `ImportRowError`, `AuditLog`).

During review, the project architecture standard was clarified: all database entities must use 32-bit integers (`int` / `IDENTITY(1,1)` in SQL Server) for primary keys and foreign keys. Route parameter constraints (`{id:int}`) must align with the integer domain models, and DTOs and OpenAPI contracts must expose `int` instead of `Guid` (or string UUIDs).

## Decision

1. **Entity Models & Schema:**
   - All primary keys across all domain entities are `int` (`Id: int`) generated via SQL Server `IDENTITY(1,1)`.
   - All foreign key relationships (`UserId`, `RoleId`, `PermissionId`, `ActorUserId`, `CreatedByUserId`, `BatchId`, `ImportBatchId`, `AssignedByUserId`) are typed as `int` or `int?`.
   - Junction tables use composite integer keys (`UserRoles(UserId, RoleId)`, `RolePermissions(RoleId, PermissionId)`).
   - Removed manual client-side key generation (`Guid.NewGuid()`); EF Core identity generation manages all primary key values upon insertion.

2. **Endpoints & Routing:**
   - All Minimal API route parameter constraints are changed from `{id:guid}` / `{roleId:guid}` to `{id:int}` / `{roleId:int}`.
   - User identity extracted from `ClaimsPrincipal` (`ClaimTypes.NameIdentifier`) is parsed via `int.TryParse(...)`.
   - Route disambiguation between `/api/v1/users/me` and `/api/v1/users/{id:int}` is cleanly preserved since route constraints only match integer paths.

3. **DTOs & OpenAPI Specification:**
   - All request and response DTOs (`UserDetailDto`, `RoleDto`, `AuditLogDto`, `ImportBatchSummaryDto`, `ImportBatchDetailDto`, `ImportRowErrorDto`, etc.) declare IDs as `int` and nullable foreign keys as `int?`.
   - OpenAPI specification generates `type: "integer"`, `format: "int32"` for all IDs and route parameters.

4. **Migrations & Database:**
   - Replaced old GUID migration with `20260904203426_InitialAuthSchemaIntIds`.
   - Migration `Down()` method cleanly drops all foreign keys, tables, and history, verified via `dotnet ef database update 0 --project backend`.
   - Migration `Up()` verified via `dotnet ef database update --project backend` against local SQL Server `MEvalDb`.

## Consequences

- **Performance & Storage:** Integer identity keys occupy 4 bytes per key compared to 16 bytes for GUIDs, significantly reducing clustered index fragmentation, memory footprint in buffer cache, and foreign key index sizes.
- **Simplicity:** URLs, route debugging, and test fixtures are simpler (e.g. `/api/v1/users/1` rather than long GUID strings).
- **Sequential Predictability:** ID values are sequential; enumeration attacks are mitigated by authentication and authorization checks (`.RequirePermission(...)`), self-protection guards, and enumeration-resistant responses on unauthenticated endpoints.
